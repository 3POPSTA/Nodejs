# Modern Express.js Development Guide

Building web applications and APIs with Express.js has evolved significantly. While legacy scaffolding tools like `express-generator` are still available, modern development often favors modular API architectures, modern view engines, or building headless APIs backed by frontend frameworks (like React, Next.js, or Vite).

---

## Modern Project Structure (Feature-Based Architecture)

Instead of the monolithic structure generated by legacy tools, modern Express applications are typically organized by feature or domain, separating concerns like controllers, routes, and services.

```text
myapp/
├── src/
│   ├── config/         # Database and environment configurations
│   ├── controllers/    # Request handlers and business logic
│   ├── middleware/     # Custom authentication, validation, and error middlewares
│   ├── routes/         # Express router definitions
│   ├── services/       # Core business logic and database queries
│   └── app.js          # Express app setup and middleware registration
├── .env                # Environment variables
├── package.json
└── server.js           # Server entry point (listens to port)
```

---

## Express.js Best Practices for Production

To build secure, robust, and maintainable Express applications in a modern ecosystem, follow these core guidelines:

### 1. Environment Variables (`dotenv`)
Never hardcode sensitive information like database credentials, API keys, or port numbers. Use the `dotenv` package to load configuration settings from a `.env` file into `process.env`.
```javascript
require("dotenv").config();
const port = process.env.PORT || 3000;
```

### 2. Centralized Error Handling
Avoid letting unhandled errors crash your application or leak stack traces to users. Always implement a centralized error-handling middleware at the very end of your middleware stack, and handle asynchronous rejections cleanly.

### 3. Security Hardening (`helmet` & Rate Limiting)
* **Helmet**: Secure your app by setting various HTTP headers automatically.
* **Rate Limiting**: Use packages like `express-rate-limit` to protect your routes against brute-force attacks and denial-of-service attempts.
```javascript
const helmet = require("helmet");
const rateLimit = require("express-rate-limit");

app.use(helmet());
app.use(rateLimit({ windowMs: 15 * 60 * 1000, max: 100 }));
```

### 4. Input Validation & Sanitization
Never trust user input. Validate and sanitize request bodies, query parameters, and route parameters using robust validation libraries such as `express-validator` or `Zod`.

### 5. Production-Grade Logging
Replace basic `console.log` statements with structured loggers like **Winston** or HTTP request loggers like **Morgan** to track traffic, performance, and application errors effectively.

### 6. Modern Testing
Ensure code reliability by writing unit and integration tests using modern testing frameworks like **Jest** or **Vitest** paired with **Supertest** for HTTP assertions.
```
